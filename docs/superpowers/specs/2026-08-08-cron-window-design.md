# Cron 时间窗口调整设计

## 目标

将 GLaDOS 自动签到工作流的触发窗口从北京时间 `12:00–18:00` 缩短为 `12:00–16:00`，保持每 15 分钟一次，并包含 `16:00` 最后一轮。

## 调度设计

工作流使用两条 UTC cron：

```yaml
- cron: '*/15 4-7 * * *'
- cron: '0 8 * * *'
```

对应北京时间：

- 第一条覆盖 `12:00`、`12:15`，持续到 `15:45`。
- 第二条仅覆盖 `16:00`。
- 不触发 `16:15` 及之后的时间。

采用两条 cron 是为了精确包含 `16:00`。若直接使用 `*/15 4-8 * * *`，会额外触发北京时间 `16:15`、`16:30` 和 `16:45`，不符合要求。

## 保持不变的行为

- 当天第一条实际到达的 cron 立即执行签到。
- 当天完整执行后，后续 cron 通过 `last_complete_date` 跳过。
- GitHub Actions 延迟某一轮时，窗口内后续 cron 仍可补偿。
- `workflow_dispatch` 手动触发继续遵守当天最多一次。
- Cache 状态、Cookie 与域名隔离、有效签到日、兑换周期、积分档位和 5 天重试逻辑均不改变。

## 文档变化

- GitHub Actions 工作流注释改为北京时间 `12:00–15:45` 和 `16:00`。
- README 的运行窗口改为北京时间 `12:00–16:00`。
- 直接 Cron 每日门控规格标注新的时间窗口。

## 验证

- 工作流 YAML 能被解析。
- cron 枚举结果精确包含北京时间 `12:00` 至 `15:45` 的 15 分钟时间点以及 `16:00`。
- cron 枚举结果不包含 `16:15`、`16:30`、`16:45`、`17:00` 或 `18:00`。
- 现有门控、签到和兑换自动化测试继续全部通过。

## 验收标准

- 每天仅在北京时间 `12:00–16:00` 窗口产生定时触发。
- 触发间隔为 15 分钟，并包含 `16:00`。
- 每日完成门控和其他业务逻辑没有行为变化。
- README、规格和工作流配置保持一致。
