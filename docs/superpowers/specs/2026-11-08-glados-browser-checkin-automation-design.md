# GLaDOS Chrome 定时签到设计

## 目标

创建一个可复用的个人 Skill，并通过 Codex 桌面应用的本地定时任务，在 Asia/Shanghai 时区每天 15:00 使用本机 Chrome 完成 GLaDOS 网页签到。

本流程独立于仓库中现有的接口签到脚本，不修改或调用这些脚本。

## 运行前提

- 本机 Chrome 已登录 `glados.network`。
- 打开 `https://glados.network/console/checkin` 后可以看到 Checkin 按钮。
- Codex 桌面应用具备 Chrome 控制权限，并可使用现有 Chrome 登录状态。
- 执行时电脑保持开机，Codex 桌面应用保持运行。

## 组成

### 个人 Skill

创建名为 `glados-browser-checkin` 的个人 Skill，保存稳定且可复用的网页操作规则。Skill 负责定义签到方法、成功条件和停止条件，不负责定义执行时间。

### 本地定时任务

创建一个独立的本地定时任务，每天 15:00 触发。任务提示词显式调用 `$glados-browser-checkin`，确保每次执行都使用相同流程。

每次运行相互独立，并在 Scheduled 中留下结果，便于检查历史执行情况。

## 执行流程

1. 使用本机 Chrome 打开 `https://glados.network/console/checkin`。
2. 等待页面加载完成并检查当前签到状态。
3. 如果页面已经显示今日已签到，则不点击按钮，直接将本次运行记为成功。
4. 如果存在可用的 Checkin 按钮，则只点击一次。
5. 等待页面反馈，确认出现“签到成功”或“今日已签到”等等价状态。
6. 记录简短结果后结束。

## 成功与失败条件

以下任一情况视为成功：

- 点击后页面明确显示签到成功。
- 页面明确显示今日已经签到。

以下情况视为失败，并停止进一步操作：

- 登录状态失效或页面要求重新登录。
- 页面无法加载。
- 找不到 Checkin 按钮，且页面也没有显示今日已签到。
- 点击后在合理等待时间内无法确认成功状态。
- Chrome 控制权限或连接不可用。

失败时报告可见现象和需要用户处理的事项。为避免重复提交，单次运行最多点击一次 Checkin 按钮，不自动反复点击。

## 安全边界

- 仅访问指定的 GLaDOS 签到页面。
- 仅执行查看签到状态和点击 Checkin 按钮所需的操作。
- 不修改账户资料、套餐、支付信息或其他设置。
- 遇到验证码、登录挑战或其他额外确认时停止并请求用户处理。
- 不与其他针对同一 Chrome 窗口的 Computer Use 任务并行运行。

## 验证

在启用每日调度前手动运行一次相同流程，确认：

- Skill 能被显式调用。
- Chrome 使用正确的已登录配置。
- 页面可打开并能识别当前签到状态。
- 成功结果可被可靠确认。

配置完成后检查定时任务为启用状态、时区为 Asia/Shanghai、执行时间为每天 15:00。首个自动运行完成后，在 Scheduled 中复核结果；如页面文案或结构变化，再更新 Skill，而不修改调度规则。
